A model can make a bad decision. It cannot invent an action.＋

Each role has exactly three allowed actions. The model scores those choices; JavaScript selects a value and constructs the fixed fields. It cannot create a “teleport” field or grant unlimited food. An allowed choice can still get a villager killed.

Candidate scores are relative preferences, not calibrated confidence. The browser evaluates one NPC at a time; this does not reproduce the CUDA service’s parallel scheduling.

How to read this experiment＋

The simulation advances independently of inference. AI ticks/sec counts applied NPC decisions in a rolling ten-second window; squad rounds/sec counts completed rounds in which every living villager received a fresh decision. Render FPS only measures drawing. Pausing, resetting, editing a prompt, or losing the selected villager can make an in-flight decision stale, so the game checks results before applying them.

WebLLM runs Qwen 3.5 0.8B on your browser GPU. The model and runtime download from Hugging Face and public CDNs; decisions then run on this device. This demo supplies symbolic world state, not screenshots. Game art: Kay Lousberg and Quaternius, CC0.
